# Notes for coding agents

MotorMod adds rideable motorcycles to Valheim (BepInEx 5 + Jötunn). The README
is for players, `docs/` for server admins and contributors. Everything learned
the hard way is written down here; read it before changing anything.

## Project rules

- Colours: black, greys, white; brown only for dirt, rust and leather. No green, olive, blue or red on the bikes (effects may be coloured).
- Fit the world: rugged, old, hand-made looks. The Hel Cycle is the reference.
- Vanilla Valheim must keep working; `-nomotormod` keeps the mod idle for a session.
- Every third-party asset gets an entry in `CREDITS.md` (title, author, link, licence, changes) before it is committed. Raw downloads and source recordings stay out of git (`.gitignore`).
- The mod ships no music; players add their own.
- Docs are plain language: short sentences, no jargon dumps.
- No leftover code: when a feature or a bike goes, everything that only served it goes with it (code, settings, assets, pipeline branches, docs, credits).

## Repo map

- `src/MotorMod/` plugin. `MotorModPlugin.cs` entry point and shared settings (GUID `com.shiva.valheim.motormod`, version in `PluginVersion` and the project's `<Version>`).
  `BikeDefinition.cs` roster: keys, prefab and display names, trail, recipe, ride stats, pose defaults, per-bike settings. The Wraith and Draugr Cycles copy the Hel Cycle (`BaseKey`): its bundle and model (a Jotunn clone made before the base is set up), another name, trail and trophy in the recipe, a tinted icon.
  `FlamingSkull.cs` the three skull helmets (a clone of the game's leather helmet carrying the skeleton trophy's skull and two flame layers), `SkullHead`, which shrinks the wearer's head bone inside the skull every LateUpdate and gives it back on removal, and `SkullIcon`, the icon renderer (a camera of its own on layer 31, the skull three-quarter from the front with its flames simulated; `--icons yaw,pitch,fill,flames` in the harness re-renders them to PNG for tuning).
  `MotorcycleController.cs` physics, mounting, headlight, wheelie, sinking, steering. `RiderPose.cs` procedural rider (IK): seat, lean, hands, feet. `EngineAudio.cs` engine sound layering.
  `BikeTrail.cs` the trail of fire and its hits. `BikeWake.cs` water wake and spray. `BikeHealth.cs` crash and ram damage on top of the game's durability (WearNTear), the rider thrown off when it breaks.
  `BikeFuel.cs` the tank. `BikeCondition.cs` the damage look (soot tiers, engine smoke, the step-down smoke and crunch). `BikePatches.cs` saddlebag interaction, no hammer removal while ridden, hit scaling, the mount panel as fuel gauge.
  `BikePrefabSetup.cs` adds the game components, the saddlebags and the durability to the bundle prefab. `BikeVanillaParts.cs` parts made from the game's own objects once they load (wreck saddlebag, iron effects, chest background, the flaming skulls).
  `MotorCommand.cs` console `motor ...`. `ConsolePatch.cs` console always on. `RidingControlsPatch.cs` no crouch toggle while riding (Left Ctrl is crouch and wheelie).
  `Soundtrack/` sea soundtrack: `SoundtrackLogic.cs` (pure playlist logic, tested by `tests/SoundtrackTests`), `MusicLibrary.cs` (music folder, measurement, cache), `SoundtrackManager.cs` (reports, host, playback, F7).
  `Harness/` sandboxed test harness, dormant without `-motorharness`.
- `unity/MotorModUnity/` Unity 6000.0.75f1 project; `Assets/Editor/MotorModBuild.cs` builds one prefab and one bundle per model in `Assets/Bikes/bikes.txt` (`hel:HelCycle`) and per prop (the saddlebag) in `Assets/Props/props.txt`; `sync_assets.sh` copies the FBX and the WAVs in (those copies are git-ignored). Bundles land in `src/MotorMod/Bundles/{osx,win}/<key>`.
- `assets/models/` Blender pipeline (`prep_bike.py`, `prep_prop.py` for the saddlebag, `make_unity_textures.py`, `render_icons.py`), configs in `configs/<key>.json`, and per model only `unity/<key>.fbx` and `unity/<key>_layout.json` in git (the Unity build reads the layout from there).
- `assets/audio/` finished clips `hel/*.wav`, `levels.json`, `manifest.json`, the pipeline `process_audio.py` and its README. Recordings in `source/` are local only.
- `tools/release/package.sh` release zips; `tools/mac/start_valheim.sh` optional Steam launcher; `tools/mac/harness.sh` and `tools/harness/{shoot,cfg}.py` harness drivers.

## Build and test (from the repo root)

```
dotnet build src/MotorMod -c Debug            # compiles; deploys DLL + bundles into BepInEx/plugins/MotorMod when the game is found
dotnet run --project tests/SoundtrackTests    # playlist logic
./unity/MotorModUnity/sync_assets.sh
<Unity 6000.0.75f1> -batchmode -nographics -projectPath "$PWD/unity/MotorModUnity" -executeMethod MotorModBuild.BuildAll -quit -logFile /tmp/unity.log
tools/release/package.sh                      # dist/ zips (checks version, changelog and bundles)
python assets/audio/process_audio.py          # sounds (needs the local recordings)
Blender --background --python assets/models/prep_bike.py -- assets/models/configs/hel.json
python assets/models/make_unity_textures.py   # textures + bikes.txt
```
Healthy load log: `hel: hel_osx -> loaded`, one `<Name> configured: seat=ok wheels=FR grips=ok headlight=ok` and one `Registered <Name>` per bike, then `MotorMod <version> loaded with 3 bikes`. Changed setting defaults only reach a settings file that is regenerated (delete `BepInEx/config/com.shiva.valheim.motormod.cfg`); the harness and normal play share that file.

## Toolchain facts

- Valheim 1.0 is Unity **6000.0.75f1** (changeset 26349cd2a5c8); bundles must come from that line. Headless Hub install: `"Unity Hub" -- --headless install --version 6000.0.75f1 --changeset 26349cd2a5c8 --module windows-mono`. The editor is at `/Applications/Unity/Hub/Editor/6000.0.75f1/Unity.app/Contents/MacOS/Unity`.
- A Unity project whose `Packages/manifest.json` lists no `com.unity.modules.*` disables every built-in module; `BuildAssetBundles` then writes bundles without their AssetBundle object and the game rejects them as "not compatible with this newer version of the Unity runtime". Grep the Unity log for "is not supported because the module".
- Mac: BepInEx 5's doorstop is x86_64, so modded Valheim runs under Rosetta (`arch -x86_64 /bin/bash ./start_game_bepinex.sh`). Bundles embed per-platform shaders: Metal for `osx`, the rest use `win`; foreign shaders render pink. A Linux dedicated server loads `win` (it never draws).
- The project targets net472 but references the game's own `netstandard.dll`: Unity 6 assemblies are built against .NET Standard 2.1. `AudioClip.GetData` also has a `Span<float>` overload a .NET Framework build cannot resolve; `MusicLibrary` calls the array version through a delegate.
- `ilspycmd` decompiles the game with `DOTNET_ROLL_FORWARD=Major`; decompiled sources are not kept. The game's prefab data (effects, items, materials) is readable with UnityPy from `Valheim.app/Contents/Resources/Data/StreamingAssets/SoftRef/Bundles` (bundle `c4210710` holds the fires and torches).
- Blender 5.2 headless: glTF imports use quaternion rotation, so set `matrix_world` and call `view_layer.update()` before `transform_apply`. FBX export with axis_forward=-Z, axis_up=Y puts Blender -Y at Unity +Z (the front). The FBX root becomes `Visual` (the body); wheels are its children; material slot order goes to `slots.txt`.
- The Mac's `rsync` is 2.6.9: no `--info=progress2`. In zsh, quote any argument that starts with `=`.

## Game API facts

- Mounting copies the ship rudder and lox saddle: `Interactable` + `Hoverable` + `IDoodadController`, `RequestControl` RPC on the owner, `Player.StartDoodadControl` + `Player.AttachStart(point, ...)`. The owner hands the ZDO to the rider (`zdo.SetOwner(sender)`), so physics runs on the rider's machine.
- Use `player.GetZDOID().UserID` as the user id everywhere; `GetPlayerID()` is a different number (mixing them zeroed the throttle).
- Inputs arrive via `ApplyControlls(moveDir, lookDir, run, autoRun, block)`: moveDir.z throttle, x steer, run = Shift, block = right mouse. Left Ctrl (wheelie) is also the game's crouch toggle.
- Doodad control ends only on: the use key, jump/attack/dodge, the attach point becoming null, more than 5 m from the controller's `GetPosition()`, or `IsValid()` false.
- Water: `Floating.GetLiquidLevel(pos, waveFactor, LiquidType.Water)`; ground probe layers terrain, Default, static_solid, piece, Default_small (`MotorcycleController.s_groundMask`).
- `Player.LateUpdate` sets `ZNet.SetReferencePosition` to the player each frame; objects outside the active area around it are unloaded (a riderless bike that drives off vanishes).
- `ZNetScene.Destroy` resets the ZNetView's ZDO at once: code that may destroy the bike inside FixedUpdate checks `m_nview.IsValid()` right after.
- Every effect prefab ZNetScene knows (fx_*, vfx_*, fire_pit, ships) carries a ZNetView. `Instantiate` makes each copy a saved world object, and stripping the ZNetView leaves a dead ZNetScene entry that throws every frame. Copy with `ZNetView.m_forceDisableInit = true` (`BikeTrail.LocalCopy`); child objects without a ZNetView copy safely. Plain effects such as `fx_Torch_Blue` are not in ZNetScene: `BikeTrail.Effect` falls back to Jötunn's prefab cache.
- Flame colours: the campfire's `flames (1)` and the blue and green torches share one material (`flameball_flipbook_gradient`, shader `Custom/Gradient Mapped Particle (Unlit)`, a grey flipbook). What makes a flame orange, blue or green is each particle system's custom vertex data (Custom1 and Custom2 colour streams) and its colour over lifetime, so `BikeTrail.Recolour` copies those modules from the torch; swapping the material changes nothing.
- Body effects follow their wearer (inherit velocity, short lives); trails take single layers and switch inherit velocity off. White streaks in night pictures are the game's wind lines, not the mod.
- Fire damage sets the Burning status by itself. `WearNTear.Damage` applies resistances, alerts wards and shows hit effects; trees and rocks need chop or pickaxe damage.
- Contact normals point from the other collider toward this one; the ground's normal stays perpendicular to the bike's forward because the bike pitches with the ground.
- Routed RPC to target 0 (Everybody) is handled locally and sent to all; `InvokeRoutedRPC(name, ...)` goes to the server. `ZNet.GetTimeSeconds()` is the shared clock (pushed every 2 s; stops while single player is paused). The music slider is `MusicMan.m_masterMusicVolume` (linear) while effects use mixer dB; the soundtrack follows the slider on the effects' curve. `UnityWebRequestMultimedia.GetAudioClip` with `compressed = true` streams MP3 for playback; `compressed = false` decodes fully so `GetData` works.
- Save data: local saves live under the game's IronGate folder; Steam Cloud characters and worlds are written back on every save. Test code must never touch real characters or worlds: the harness moves the save root with `Utils.SetSaveDataPath` before `FejdStartup.Awake` and uses the game's throwaway "Odev" profile and its own world. Steam must be running to get past the menu.
- Equipment: `VisEquipment.AttachItem` puts a helmet's `attach` child under the `Helmet_attach` joint below the Head bone; `HelmetHairType.Hidden` hides hair and beard.

## Design facts

- Trail (`BikeTrail`): the campfire's `flames (1)` copied to the bottom of both tyres, emitting per metre (10 at walking pace, double at top speed), world space, no inherited velocity. Visuals on every client, hits on the rider's machine, enemies only: within 1.1 m of the line the rear tyre drew plus the creature's radius, once a second per creature, fire damage (Burning). `fire_blue` and `fire_green` are the same flames recoloured from the torches, with a coloured light at the rear wheel.
- Wheelie: lift 560, gravity 430 x cos(pitch), damping 3.2, scaled by 1/ease squared (`WheelieEase` per bike); past 62 degrees the front is set down, nothing else happens. The visible bike pitches about the rear axle; colliders stay on the root. Pitch syncs in the ZDO (`mm_pitch`).
- Frames: `Visual` carries the -90 degree import rotation about x (its local y points backwards). `MotorcycleController.BikeFrame` is the root's axes carried by the visible bike; the rider pose works in it.
- Steering: the model's steering assembly is a "Steer" part (prep_bike.py `steer` config: include by name or used material, boxes, or in front of the plane through the steering axis; `split` cuts straddling parts such as the Hel Cycle's chains), with the front wheel inside it, and the grips and headlight markers on it. `SteerAxisBottom/Top` markers give the axis (front axle to the steering head). The bars turn by the eased steering times `HandlebarTurn` (22) at walking pace down to `HandlebarTurnFast` (5) at top speed, but never further than the rider's outside hand can follow: `RiderPose.Follow` tries each angle (the chest twists 0.9 x the bar angle and swings the shoulder), lets the hand slide up to 6 cm in along its grip, and caps the turn where the arm would fall more than 1 cm shorter than with the bars straight (`m_barReachRight/Left`; the Hel Cycle reaches the full 22). The harness `measure` line prints the bars, those caps and each knuckle's distance to the bar's surface. The steering is synced (`mm_steer`), so other players see bars and lean. `ApplySeatOffset` straightens the bars before placing the grips. Positive angles about the up-and-back axis turn the wheel right.
- Rider feet (`RiderPose`): on the pegs while riding. Under 0.5 m/s on land (not on water, no wheelie) `m_feetDown` blends to 1 over 0.4 s and each foot goes to the ground found by a ray 0.32 m out and 0.08 m forward from the hip (the bike's own colliders skipped), the ankle `AnkleHeight` above it; ground beyond the leg's reach is tiptoed (the foot goes as far as it can, toes pointing down to the ground). The harness `measure` line prints `feet down` and each sole's height above the ground.
- Durability: the game's WearNTear, set up like a boat's or cart's (no roof or support wear, `m_staticPosition` false, not burnable, snow-immune, ash only to 10 %), 3000 health (`MaxHealth`) in `ZDOVars.s_health`. The hammer shows its bar, repairs it near a forge (`Player.Repair` needs the piece's station) and may remove it near a forge (`Piece.CanBeRemoved` is patched false while ridden; the game itself forbids hammering boats and carts). Nothing repairs itself. `BikeHealth` adds crash damage above 8 m/s straight into a surface (`WearNTear.ApplyDamage`, owner only), rams (the bike's own speed toward the creature, 4 blunt per m/s from 4 m/s, once a second per creature, never players or tamed animals) and impact damage to any IDestructible it crashes into. `HitDamageScale` scales hits in a `WearNTear.RPC_Damage` prefix. Any break (hits, crash, monsters, sinking via `WearNTear.Remove`) runs the game's `Piece.DropResources`: the whole recipe for a bike a player built, a third for one nobody built (console spawns), nothing on free-build worlds. The bike's `Piece` has no `m_destroyedLootPrefab` (by design since 0.7.0), so the materials drop loose (ItemDrops) where it broke: on the ground, or sinking to the seabed in deep water, where they are unrecoverable (the game has no diving).
- Condition look (`BikeCondition`): the game's ships and carts swap `m_new/m_worn/m_broken` objects at 75 % and 25 % (`WearNTear.SetHealthVisual`, `m_switchEffect` on each step down; the bike has no such objects, so that code returns at once). The bike polls `BikeHealth.Fraction` (the ZDO health, so every client agrees) and tints its body renderers (not the saddlebags, headlight glow or particles) per material slot through `MaterialPropertyBlock`s: `_Color` and `_Glossiness`/`_GlossMapScale` x0.72/0.6 worn, x0.45/0.35 wrecked, cleared when fresh. Wrecked, a looping half-size world-space local copy of `vfx_Damaged_Karve`'s particle system (`EngineSmoke` under Visual, between the axles) emits 4/s. On a step down the owner alone plays `WearNTear.m_switchEffect` (vfx_Damaged_Karve + sfx_metalbars_break): effect prefabs are network objects and would double up if every client spawned them. Hit effect vfx_HitSparks + sfx_metalbars_hit; destroyed: smoke + sparks + crunch (`BikeVanillaParts.Effects`). Never spawn the fireplace `smoke` prefab from a bike: it is a rigidbody, and a stream of them inside the bike's colliders while it ground against a wall killed the game process twice, with no exception and no crash report.
- Crash break-up: `BikeHealth` sets `m_breakReason = "crash"` when the crash damage will take the bike to 0, and `OnBroken` (owner, inside `WearNTear.Destroy`) plays `MotorModPlugin.CrashBreakEffect` (fx_dynamite_explosion + sfx_bombdynamite_explosion: the look and the sound only, never the bombs' area damage). `CrashDamage` 100 per m/s above `CrashSpeed` 8, and from `FatalCrashSpeed` 24 the damage is at least the bike's health: broken outright. The impact speed is the real one (`Collision.relativeVelocity`): about 26 m/s at boost on grass, since ground friction keeps the real speed under the bike's own 36, so a boost head-on breaks any bike, while a plain top-speed head-on (about 15 real) costs 700 of 3000. The harness wall test with `--boost` sets `CfgAcceleration` to 30 for the run because 22 m of lane is too short otherwise.
- Wreck bag (`BikeVanillaParts`): the game's CargoCrate cloned as `MotorModSaddlebag` (floats, holds items, vanishes when emptied), the crate mesh swapped for the saddlebag, 2x1 slots like the saddlebags, floating 0.12 m higher than the crate. It is the saddlebags' `m_destroyedLootPrefab` only, so a broken bike leaves one bag with what its bags held while its own materials lie loose. Almost every material sinks in the game (only tar and wood float); loose items vanish after an hour away from players and bases.
- Fuel (`BikeFuel`): metres left in the ZDO key `mm_fuel`; tank `TankKm` (6.67), the fuel in `BikeDefinition.FuelItem/FuelMetres` (Surtling core, 1334 m: five fill the tank); nothing else burns (coal went in 0.7.0). Burns the ground really covered while the throttle is open (not the bike's own speed, which friction keeps well above the real one on land), times `BoostBurn` (2). Empty: no throttle, engine flag off, can sit but not ride. Built empty. Shift+E (`Interact` with alt) pours cores from the bag then the saddlebags until full; `UseItem` (hotbar) pours that item. Filling claims the ZDO, so it is refused while someone rides, while the bike rolls (`MotorcycleController.Standing`: own and synced speed under 0.5 m/s; the hover text drops the fill lines meanwhile) and while someone has the bags open. `[Fuel]` settings are `IsAdminOnly`: Jotunn syncs them from the server.
- Saddlebags: a `Saddlebags` object under Visual, in the bike's frame at rest, with two trigger BoxColliders and the game's Container (2x1, `m_rootObjectOverride` = the bike's ZNetView) on the same object (the hover only finds a Hoverable on the hit collider's own object, else the rigidbody's). Opening a Container hands the ZDO to the opener, so the bags are shut while ridden and mounting is refused while they are open. Placed per spawn just outside the bike's own vertices over the rear axle (`HalfWidthAt`), height 0.9 wheel radii up, `SaddlebagForward/Up/Scale` per bike. Unity's FBX import mirrors x, so the bag model's front faces -x.
- Flaming skulls (`FlamingSkull`): clones of `HelmetLeather` (armour 0, hair and beard hidden) whose attach model is the `TrophySkeleton` skull with two flame layers (a crown in local space, a trail in world space) copied from the plain, blue or green torch's root particle system (never the campfire's `flames (1)`: its 1.5 x 2 m vertical-billboard tongues streak behind a moving wearer), a glow light and a pickup collider. `SkullHead` sizes the skull from the wearer's scale (not the head bone's) and shrinks the head bone (`HeadShrink` 0.6).
- Fuel gauge: a `Hud.UpdateMount` postfix shows the game's mount panel while riding a bike, its stamina bar as the tank, health bar hidden.
- Console spawn, repair, fuel, remove and removeall require `Terminal.m_cheat`.
- Blocked bike: with a contact pressing on the front and the bike moving under 40 % of its own speed for 0.15 s, the speed bleeds to the real one. Ground friction alone keeps the real speed on land well below the bike's own, so never test the ratio without the contact.
- Water: the bike stays up only while planing (boost above 60 % of top speed, or a wheelie over 8 degrees); otherwise it settles (1.25 m over `SinkSeconds` (1.5, floor 0.5) standing, `CruiseSinkRate` (0.5) times that cruising at top speed without boost: 3 s). Swamped, the engine floods and 1.5 s later it breaks apart. Planing lifts it back at 0.5 m/s. Braking from cruise takes 2 s, so a bike that stops on deep water is lost by design (no refuelling at sea); the harness holds `--water` bikes up (`m_noSink`) until a test studies sinking. Shallow water: it rests on the bottom.
- Wake (`BikeWake`): the Karve's flat foam layers plus spray from fx_float_hitwater (mist) and fx_WaterImpact_Big's droplets rendered Stretch, placed on the water surface; shown on every client from the shared `mm_onwater` flag.
- Music (`MusicLibrary`): songs are the MP3/OGG/WAV files in `BepInEx/config/MotorMod/music` (setting `MusicFolder`), matched between players by file name. New or changed files are decoded once and measured (exact length; ITU-R BS.1770 loudness with pyloudnorm's filters, target -18 LUFS; within 0.15 dB of pyloudnorm), a slice per frame; results cached in `.motormod-index.tsv`. Dedicated servers (batch mode) skip it.
- Soundtrack playback (`SoundtrackManager`): fades in over 2 s; out over `FadeOutSeconds` (30) while the song runs on and the rider has left the water, otherwise (mute key, song end, unlisted) over 1.5 s. The host's `GraceSeconds` (30) keeps the playlist running meanwhile, so a rider back within it is still in time; after it the playlist pauses. The RPC names are `MM_Soundtrack_*`.

## Test harness

- `tools/mac/harness.sh start|stop|status|log` launches the game with `-motorharness`: own save folder, throwaway character and world, a small window that never grabs the mouse, keyboard and mouse locked so stray keys cannot disturb a test, god and ghost mode during runs. Ready in about 50 s; a new DLL needs stop + start. `stop` restores the window settings.
- `python tools/harness/shoot.py [bikes] [options]` writes a request, waits for the result and copies the pictures. Options: `--views` (right, left, front34, front34l (the two front corners, 45 degrees off the nose: Shiva's favourite angle, never straight into the face and headlight), rear34, top, front, hands, bags, bagsleft, riderhead, riderheadside, riderheadback; rides also shoot moving, movingside, movingfront and movingfrontl at four moments), `--steer -1..1` (bars held for the pictures), `--skull <helmet prefab>`, `--gear <item prefabs>` (armour, cape, a sheathed weapon), `--biome <Plains|AshLands|...>` (a flat spot with a clear lane in that biome, nearest the world's centre, instead of the usual stage), `--icons yaw,pitch,fill,flames` (the skull icons as PNGs), `--time`, `--ride`, `--boost`, `--water`, `--music`, `--wheelie`, `--targets`, `--ram`, `--wall`, `--sink`, `--seadry`, `--songs`, `--refund <bike>`, `--fuel <bike>`, `--storage <bike>`, `--ui <bike>` (screenshots of the game window with the HUD), `--condition <bike>` (the three damage states, photographed), `--wall <piece> --boost` (the fatal crash and its fireball, photographed), `--fx`, `--prefabs`, `--inspect <prefabs>` (wear objects, effect lists, material shaders), `--census`, `--probe`, `--markers`. Every bike shot logs where its saddlebags went and how many bike vertices lie inside them (must be 0).
- Standing pictures show the rider with the feet down; after `--ride` the bike is still rolling, so those show the feet on the pegs. The `measure` line has the hand, bar, foot and seat numbers in centimetres.
- Harness bikes are filled up on spawn (bikes are built empty). Spawned bikes have no builder: set `Piece.m_creator` before expecting a full refund. The camera follows the player's `m_lookYaw`/`m_lookPitch`, not `SetLookDir`: aim it over several frames from the camera's own position (`HarnessChecks.Aim`).
- All views of a bike render in one frame from the coroutine after `RiderPose.Apply()`. Never pause the game to freeze a pose: the pose is relative, and at timeScale 0 the animator stops resetting bones. Batch mode renders the rider stale; use the window.
- Each bike first returns to the stage. Land rides run along +x; the Elder's boss stone stands about 26 m along and cannot be cleared. The water stage needs 500 m of open water along +x. Requests clear stray effects near the stage.
- The music test shortens the host's grace to 4 s for its pause check and restores it.

## Pipeline facts

- `prep_bike.py`: centres, orients and scales the model, decimates, finds wheels, seat, grips and headlight, splits off the steering assembly, joins Body/Steer/WheelFront/WheelRear with wheel origins on the axles, exports FBX + GLB + textures + layout JSON + renders (`<key>_steer_*.png` show the steering part green and the axis yellow). `PARTS_DUMP=1` (or `only`) writes `<key>_parts.json` with every body part's box and materials in Unity axes. Config keys: source, target_length, length_axis, front, wheels, wheel_exclude, hide, seat, seat_override, grips, headlight, decimate_cap, total_tris_cap, palette, licence, steer (top, include, include_boxes, margin, split, split_margin). Unused material slots are removed per joined object (empty slots shift the materials in Unity).
- `prep_prop.py` (the saddlebag): joins, turns (config `width_axis`, `front`, `up`), scales to `width_m`, origin on the middle of the back face, four check renders. Layout `kind: prop` sends it to `Assets/Props`.
- `make_unity_textures.py` (always converts every model and rewrites bikes.txt and props.txt): glTF metallic (B) and roughness (G) become Unity metallic (R) and smoothness (A); the palette rule keeps brown hues and greys other saturated colours (it turns dark red-brown leather blotchy grey, so all-leather models use `"palette": "leather"`, which moves every hue into the brown band instead); tyre materials become rubber.
- Sounds: seamless loops by matching the audio before the loop start; loudness ladder (LUFS) startup -22, idle -24, blips -17, accel -15, cruise_high -18, cruise_fast -15, shut-off -22, peaks -1 dBFS.

## Known gaps

- The engine recordings are the author's own and stay out of git under neutral names (`assets/audio/source/fatboy_startup_idle.mp3`, `fatboy_114_ride.mp3`, `shovelhead_start_idle.mp3`); never name where they were published.
- Multiplayer (trails, wheelie pitch, wake, soundtrack, fuel, saddlebags, feet) is written for it but only single player has been tested. Bike settings are per player, not synced from the server, except `[Fuel]`.
- The Wraith and Draugr Cycles share the Hel Cycle's model, sounds and fuel; only the flames and the recipe's trophy differ.
- Linux clients are untested; bundles are about 28 MB per platform.
